## 🚀 About the Event

**IMPETUS.AI** bridges the gap between academic theory and real-world industry practice. Many students study Artificial Intelligence and Machine Learning theory from textbooks but struggle with writing functional, real-world project code.

**The IMPETUS.AI Solution:**
An immersive, experiential ecosystem where students build a portfolio-ready machine learning project from scratch under structured mentorship.

### Key Highlights
- **Focus on Edge-AI:** Proving that AI models can run locally and efficiently in the physical world.
- **Strict Development Environment:** Teams build models inside VS Code using open-source libraries (NumPy, Pandas, Scikit-Learn) with zero integrated AI coding assistants allowed.
- **Presentation & Pitch:** Emphasis on articulating model logic to expert judges.
- **Future Exposure:** Top-performing models earn an exclusive spot at the upcoming Tech Expo.

---

## 🗓️ Event Structure

The competition is structured into a 2-phase experience:

1. **Phase 1 (Training Boot Camps):**
   - 2-day, 90-minute live coding boot camp.
   - Intensive "ONE SHOT" session establishing baseline logic in data preprocessing, model selection, and training mechanics.
2. **Phase 2 (The Event Sprint):**
   - High-octane 1-day competitive sprint.
   - Participants write, optimize, and test their own functional machine learning application locally.

## 📜 Event Rules

1. Use only approved AI tools (e.g., ChatGPT, Claude, or Gemini) for guidance, code generation, debugging, and documentation.
2. Participants must build the project themselves; AI tools are assistants only.
3. Follow the complete ML pipeline while developing the project.
4. Development environment must strictly be **Visual Studio Code (VS Code)**.
5. No VS Code AI coding extensions or auto-completion plugins are allowed during the event.
6. External AI coding assistants (Antigravity, Cursor, Windsurf, GitHub Copilot, Replit AI, etc.) are prohibited.
7. Internet usage is restricted to approved AI tools and official documentation only.
8. Participants must explain their code, model, dataset, and pipeline during evaluation.
9. Use legal and publicly available datasets or datasets provided by organizers with proper attribution.
10. Submit complete project source code, trained model (if applicable), README, and pipeline explanation.
